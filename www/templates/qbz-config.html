Settings
General
Max encoded bits/rate. Tracks not available at the selected quality are streamed at the highest quality available for the subscription.
How much audio to buffer before playback starts. A larger buffer can help reduce the likelyhood of audio glitches on a slow or poor quality network.
Volume
The volume to set when a client App connects, so an App that has never played to this renderer cannot arrive at its own remembered level.
Off: Leave the volume where it is. Forced when Volume is set to Fixed (0dB), since the renderer does not attenuate at all in that mode.
Adjusts the volume of all songs played so that they sound as though they are of equal loudness.
The loudness all songs are matched to. Quieter targets leave more headroom for the peaks in dynamic recordings.
-14 LUFS: What the streaming services use.
-18 LUFS: Quieter, and the usual choice for classical and jazz.
-23 LUFS: The EBU R128 broadcast standard. $_normalization_hint
Playback
When buffered: Playback starts after the track has been buffered.
After download: Playback starts after the track has finished downloading.
Enabled: Cache tracks. Gapless playback is supported.
Disabled: Stream only, do not cache the track. Gapless playback is not supported.
Auto: The size of the in-memory track cache is based on the amount of physical memory.
Number: Set a specific size for the in-memory track cache.
How much of the card cached tracks may occupy. Players with less than 2 GB of memory cache to the card; the rest keep tracks in memory and never write to it. The oldest tracks are removed once the limit is reached. $_disk_cache_hint
Play consecutive tracks without a gap of silence between them. Requires the Track cache to be enabled. Works on every player, including the small boards — those hold the next track on the card rather than in memory, so it needs the card cache to be working. $_gapless_hint
Auto: Calculate the buffer length based on sample rate of the track.
Number: Set a specific the buffer length.
Advanced
The renderer has additional tuning settings this page deliberately does not show. They are reachable and settable over SSH. Each takes effect the next time the renderer starts, so restart it from Renderer Config afterwards, and note that this page rewrites every setting it owns on each restart — the ones below are not among them, so they stick.

See what the renderer is currently set to
pibuz settings show

Buffer more decoded audio — the cushion between a network stall and a click. Auto picks 6 seconds, or 2 on a player with under 2 GB of memory. Raise it on a player on weak WiFi.
pibuz settings set audio.pcm_ring_ms 4000

Download further ahead — seconds of compressed audio fetched in advance of playback, 2 to 60. This is the memory a playing track occupies, so raising it costs RAM.
pibuz settings set audio.stream_window_seconds 20

Resize the in-memory track cache — the RAM downloaded tracks are held in, so a repeat or a gapless hand-off does not go back to the network. auto takes 17 % of physical memory, capped at 512 MB: about 150 MB on a 1 GB player, about 340 MB on 2 GB, and the cap from roughly 3 GB up. A Hi-Res FLAC is 60–170 MB, so even the cap leaves room for the playing track and the prefetched next one; what does not fit spills to the disk cache above. Accepts auto or a size in MB.
pibuz settings set audio.memory_cache_mb auto

Change the volume curve — how a percentage becomes a level. Perceptual matches MPD, linear makes the slider unusable below its top tenth.
pibuz settings set audio.volume_curve linear

Stop the audio thread running at real-time priority — only worth trying if the renderer is starving something else on a busy player.
pibuz settings set audio.writer_rt_priority off

Name the mixer explicitly — only needed if hardware volume cannot find the DAC’s mixer on its own.
pibuz settings set audio.alsa_mixer_device hw:0
Troubleshooting
1. System Config: Turn ON Debug logging.
2. System Config: CLEAR System logs.
3. Renderer Config: RESTART Qobuz Connect.
3. Reproduce the issue.
4. Click DOWNLOAD. The log file will be in the default Downloads folder.
5. Post the file in the Support section of the Moode Forum along with a description of the issue.
The log file is named "qobuz-connect-HOSTNAME-DATE-TIME.tar.gz"
